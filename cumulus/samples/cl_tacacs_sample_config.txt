===============================================================================
Hand-apply configuration guide - TACACS+ client (all Cumulus switches)
===============================================================================
Same commands on every switch (cl-sp-1/2, cl-lf-1..4, cl-bl-lf-1/2) except the
source IP. Server: tac_plus-ng on the Kubernetes cluster, 192.168.122.63:49
(kubernetes/README.md, --tags tacacs), reached through the management VRF
(eth0, vrf mgmt). Syntax checked against NVUE on Cumulus Linux 5.4.0
("nv set system aaa tacacs -h"); NOT yet applied to any switch.

Two ways to apply: by hand (this file) or with the Ansible playbook (see
"Ansible alternative" at the end). Do ONE of them per switch, not both.

Before pasting by hand:
  * Replace <TACACS_KEY> with the contents of kubernetes/artifacts/tacacs-key
    (git-ignored).
  * Keep a second ssh session open and use the rollback timer (see Apply).

Method order: TACACS first, local as the fallback ("authentication-order").
The local accounts that automation depends on are EXCLUDED from TACACS, so they
keep working whether the server is up, down or rejecting them:
  cumulus   Ansible (remote_user in cumulus/ansible.cfg), sudo
  monitor   NVUE REST API / BGP monitoring (nvue_api_user)
This differs from the Arista setup, where admin/monitor are mirrored on the
server because EOS has no exclude list. No server change is needed for Cumulus.

TACACS-only users (same server users as on the Arista switches):
  netadmin, vivek  priv-lvl 15  admin
  netops           priv-lvl 1   read-only
tac_plus-ng offers password login via PAP (password pap = login), so the
authentication mode below is pap.

-------------------------------------------------------------------------------
Before you start
-------------------------------------------------------------------------------
# Anything already staged but not applied? MUST print nothing - otherwise
# "nv config apply" below applies that half-finished work too.
nv config diff

# Server reachable from the mgmt VRF? Should print "open". (nc is not installed
# on Cumulus, so use bash's /dev/tcp.)
sudo ip vrf exec mgmt timeout 3 bash -c '</dev/tcp/192.168.122.63/49' && echo open || echo "closed/filtered"

# NVUE refuses to apply ("Install the tacplus-client package before enabling
# TACACS+ client use") without the tacplus-client package. Install it (the mgmt
# VRF has the route out):
sudo ip vrf exec mgmt apt-get install -y tacplus-client
# No repo access: fetch the .deb elsewhere, scp it over, "sudo dpkg -i <file>.deb".
# If apt cannot find it: "apt-cache search tacplus" and install what it lists.

# Current order is "1 local" only:
nv show system aaa authentication-order

-------------------------------------------------------------------------------
Step 1 - TACACS+ server (replace <TACACS_KEY>)
-------------------------------------------------------------------------------
nv set system aaa tacacs enable on
nv set system aaa tacacs vrf mgmt
nv set system aaa tacacs timeout 5
nv set system aaa tacacs server 1 host 192.168.122.63
nv set system aaa tacacs server 1 port 49
nv set system aaa tacacs server 1 secret <TACACS_KEY>

# Source address of the requests: the switch's own mgmt IP. The server only
# accepts clients in 192.168.122.0/24 (tacacs_clients), so this must be eth0's.
#   cl-sp-1 .32   cl-sp-2 .33   cl-lf-1 .34   cl-lf-2 .35
#   cl-lf-3 .36   cl-lf-4 .37   cl-bl-lf-1 .38   cl-bl-lf-2 .39
nv set system aaa tacacs source-ip 192.168.122.34      # <- this switch

-------------------------------------------------------------------------------
Step 2 - Authentication, accounting, excluded accounts
-------------------------------------------------------------------------------
nv set system aaa tacacs authentication mode pap
nv set system aaa tacacs accounting enable on
nv set system aaa tacacs accounting send-records all

# Keep the automation accounts local-only (do NOT skip: without these, Ansible
# and the REST API monitor are checked by the server, which has no "cumulus"
# user, and are rejected).
nv set system aaa tacacs exclude-user cumulus
nv set system aaa tacacs exclude-user monitor

# TACACS first, local second.
nv set system aaa authentication-order 1 tacacs
nv set system aaa authentication-order 2 local

-------------------------------------------------------------------------------
Apply (do this on ONE switch first, e.g. cl-lf-1)
-------------------------------------------------------------------------------
# Should list only the tacacs / authentication-order changes above:
nv config diff

# Rolls back by itself unless confirmed within 5 minutes. Keep this ssh session
# open, and test from a SECOND one before the timer runs out.
nv config apply --confirm 5m -y

# From a second ssh session / the Ansible host:
#   ssh netadmin@192.168.122.34    -> logs in, "sudo -l" works (priv-lvl 15)
#   ssh netops@192.168.122.34      -> logs in, no sudo (priv-lvl 1)
#   ssh cumulus@192.168.122.34     -> still works (excluded, local)
#   ansible cl-lf-1 -m ping        -> still works
#   curl -k -u monitor:<pw> https://192.168.122.34:8765/nvue_v1/system  (REST API)
# Then make it permanent:
nv config apply --confirm-yes
# or let the timer expire to roll back.

-------------------------------------------------------------------------------
Verify
-------------------------------------------------------------------------------
nv show system aaa authentication-order
nv show system aaa tacacs
# Server side (shows the switch source IP and each login):
#   kubectl -n aaa logs deploy/tacacs -c tac-plus-ng
# Fallback test: kubectl -n aaa scale deploy/tacacs --replicas=0, wait ~10 s,
#   ssh cumulus@<switch> still works; netadmin/netops are refused (no local
#   account). Scale back to 1 afterwards.

VERIFIED on cl-bl-lf-1: a priv-lvl 15 user (vivek) gets full sudo, no sudoers
change needed. "sudo -l" shows "(ALL : ALL) ALL" (password required) plus the
stock "(root) NOPASSWD: /usr/bin/vrf task set default [0-9]*" rule. netops
(priv-lvl 1) still to be checked: "sudo -l" should refuse.

NOTE - to confirm on the first switch (not verifiable until TACACS is on):
the user mapping. Cumulus maps TACACS users to local "tacacs0".."tacacs15"
accounts by priv-lvl; check "id" / "sudo -l" for netadmin vs netops after login
and adjust the server's priv-lvl or "nv set system aaa tacacs authentication
per-user-homedir" if the result is not as listed above.

-------------------------------------------------------------------------------
Ansible alternative (cumulus/tacacs.yml, role cumulus_tacacs)
-------------------------------------------------------------------------------
Does the same as Steps 1-2 + Apply, but it is NOT part of site.yml: run it on
purpose. Run from the cumulus/ directory on the Ansible host.
Needs kubernetes/artifacts/tacacs-key (git-ignored), or -e tacacs_key=<key>.
Settings (server, port, timeout, excluded users) are in group_vars/all/vars.yml.

# 1. Dry run on the first switch - changes nothing:
ansible-playbook tacacs.yml --limit cl-lf-1 --check

# 2. Real run on the first switch. Per switch it: installs tacplus-client
#    (apt-get install in vrf mgmt) if missing, checks TCP/49, refuses
#    to go on if other NVUE changes are staged, stages the config, runs
#    "nv config apply --confirm 5m", checks TACACS is active, then pauses for
#    your login test and runs "nv config apply --confirm-yes". If a task fails first, the switch rolls back itself.
ansible-playbook tacacs.yml --limit cl-lf-1

# 3. Test logins (netadmin, vivek, netops) as in "Apply" above, then the rest
#    of the switches, one at a time:
ansible-playbook tacacs.yml

# Test window: after the apply the playbook PAUSES (rollback timer 10m, see
# tacacs_confirm in group_vars/all/vars.yml). Test the logins from a second
# session, then press Enter to run "nv config apply --confirm-yes". Ctrl-C then "a" aborts
# and the switch rolls back by itself. -e tacacs_pause_for_test=false skips the
# pause and confirms straight away.
# Ansible logs in as "cumulus", which is excluded from TACACS, so it keeps working.

# NVUE groups: Cumulus maps each priv-level to a real local account (netadmin and
# vivek -> tacacs15, netops -> tacacs1) and a session gets the groups of THAT
# account, not of the login name. Without nvshow/nvset/nvapply, "nv show" says
# "You do not have permission". By hand, per switch (then log out and in):
#   sudo usermod -aG nvshow,nvset,nvapply tacacs15
#   sudo usermod -aG nvshow tacacs1
# The playbook does this too; to run only that part:
#   ansible-playbook tacacs.yml --limit <switch> -e tacacs_install_confirm=n --tags nvue_groups

-------------------------------------------------------------------------------
Rollback
-------------------------------------------------------------------------------
nv unset system aaa tacacs
nv unset system aaa authentication-order
nv set system aaa authentication-order 1 local
nv config apply -y
