===============================================================================
Hand-apply configuration guide - LEAF02 (cl-lf-2)
===============================================================================
Step-by-step NVUE configuration for cl-lf-2, applied by hand one layer at a
time. Each step stages "nv set" commands, applies them, then verifies the
result before moving on, so you can see what each layer adds.

Every line starting with "#" is a shell comment, so a whole step block can be
pasted into the switch CLI as-is. The same commands are generated by the
Ansible templates in roles/cumulus_underlay and roles/cumulus_overlay.

Role in fabric : leaf (not a border leaf)
Management IP  : 192.168.122.35
Loopback IP    : 10.0.0.12/32
VTEP IP        : 10.0.0.12
Router ASN     : 65012
Fabric MTU     : 9216 (9215 on swp links)
Uplinks        : swp1 -> cl-sp-1, swp2 -> cl-sp-2

-------------------------------------------------------------------------------
Before you start
-------------------------------------------------------------------------------
# Is anything already staged but not applied? (should print nothing)
nv config diff

# Throw away a half-staged change if you need to start a step again
#   nv config detach

# Leftover pre-NVUE config: the old Ansible roles wrote ifupdown2 fragments
# (00-loopback / 10-uplinks / 20-vxlan / 30-external .intf) here. NVUE's
# /etc/network/interfaces still sources this directory, so they get merged
# with NVUE's config and break ifreload, e.g.
#   "vni10010: mixing traditional vxlan with single vxlan device is not supported"
#   "RTNETLINK answers: Address already in use"
# Move them out before step 1 (should list nothing afterwards):
ls -l /etc/network/interfaces.d/
sudo mkdir -p /root/pre-nvue-backup
sudo mv /etc/network/interfaces.d/*.intf /root/pre-nvue-backup/ 2>/dev/null
ls /etc/network/interfaces.d/
# Old per-VNI devices still in the kernel (leafs only; none = no output)
ip -br link | grep -E "^vni[0-9]+"
#   remove any listed with:  sudo ip link del <name>

# NVUE validates the whole pending revision on "nv config apply", so a step
# is only accepted when everything it references (peer-group, vrf, ASN) is
# staged in the same step or was already applied.

-------------------------------------------------------------------------------
Step 1 - Loopback and fabric uplinks
-------------------------------------------------------------------------------
# Loopback = router-id, BGP source of truth and later the VTEP (tunnel) IP.
nv set interface lo ip address 10.0.0.12/32

# Uplinks to the spines. No IP addresses: BGP unnumbered (step 2) peers over
# the automatic IPv6 link-local address. MTU 9215 leaves room for the 50-byte
# VXLAN header on top of jumbo tenant frames.
nv set interface swp1 link state up
nv set interface swp1 link mtu 9215
nv set interface swp2 link state up
nv set interface swp2 link mtu 9215

nv config apply -y

# Verify
nv show interface lo ip address           # 10.0.0.12/32
nv show interface --view=brief            # swp1/swp2 up, MTU 9215
nv show service lldp neighbor             # swp1 -> cl-sp-1, swp2 -> cl-sp-2

-------------------------------------------------------------------------------
Step 2 - Underlay BGP (eBGP unnumbered) + EVPN address family
-------------------------------------------------------------------------------
# Global BGP identity. Set at "router bgp" level, not per vrf, so that every
# BGP instance (vrf default now, vrf TENANT_A in step 4) inherits it. Without
# this, enabling BGP in TENANT_A fails with:
#   "BGP requires autonomous-system to be set globally or in the VRF."
nv set router bgp autonomous-system 65012
nv set router bgp router-id 10.0.0.12
nv set router bgp enable on

# Peer-group shared by both uplinks. "remote-as external" = accept any ASN
# different from ours (each spine has its own). BFD gives sub-second failure
# detection. The same session carries IPv4 (loopbacks) and l2vpn-evpn (overlay).
nv set vrf default router bgp peer-group UNDERLAY remote-as external
nv set vrf default router bgp peer-group UNDERLAY bfd enable on
nv set vrf default router bgp peer-group UNDERLAY address-family ipv4-unicast enable on
nv set vrf default router bgp peer-group UNDERLAY address-family l2vpn-evpn enable on

# Neighbors are interfaces, not IPs (unnumbered).
nv set vrf default router bgp neighbor swp1 type unnumbered
nv set vrf default router bgp neighbor swp1 peer-group UNDERLAY
nv set vrf default router bgp neighbor swp2 type unnumbered
nv set vrf default router bgp neighbor swp2 peer-group UNDERLAY

# Advertise our loopback; install up to 2 equal-cost paths (one per spine).
nv set vrf default router bgp address-family ipv4-unicast network 10.0.0.12/32
nv set vrf default router bgp address-family ipv4-unicast multipaths ebgp 2
nv set vrf default router bgp address-family l2vpn-evpn enable on

nv set vrf default router bgp enable on

nv config apply -y

# Verify
nv show vrf default router bgp neighbor           # swp1, swp2 established
sudo vtysh -c "show bgp summary"
sudo vtysh -c "show bgp l2vpn evpn summary"       # EVPN AF up (0 routes yet is fine)
ip route show 10.0.0.11/32                        # 2 nexthops (once cl-lf-1 is up)
ping -c3 -I lo 10.0.0.1                           # spine loopback reachable

-------------------------------------------------------------------------------
Step 3 - VXLAN tunnel endpoint (VTEP)
-------------------------------------------------------------------------------
# Turns on VXLAN and sources all tunnels from the loopback. No VNIs yet.
nv set nve vxlan enable on
nv set nve vxlan source address 10.0.0.12

nv config apply -y

# Verify
nv show nve vxlan                                 # enabled, source 10.0.0.12

-------------------------------------------------------------------------------
Step 4 - Tenant VRF and L3 VNI (symmetric IRB)
-------------------------------------------------------------------------------
# VNI 10100 is the L3 VNI: routed traffic between subnets (and to external
# networks) crosses the fabric in this VNI.

# 4a - Global BGP identity (same lines as step 2, repeated so this step works
# on its own). BGP in TENANT_A needs an ASN set globally; a switch configured
# from the older sample only has it under "vrf default" and fails with:
#   "BGP requires autonomous-system to be set globally or in the VRF."
# Already set? Re-setting the same value is a no-op.
nv set router bgp autonomous-system 65012
nv set router bgp router-id 10.0.0.12
nv set router bgp enable on

# 4b - Remove the hand-made L3 VNI mapping left by the older sample (see 4d).
# If they were never configured, NVUE has nothing to remove - any message
# printed here can be ignored.
nv unset bridge domain br_default vlan 100
nv unset interface vlan100

# 4c - BGP instance inside the vrf (inherits ASN/router-id from 4a).
# "redistribute connected" turns the tenant subnets into EVPN type-5 routes.
nv set vrf TENANT_A router bgp enable on
nv set vrf TENANT_A router bgp address-family ipv4-unicast enable on
nv set vrf TENANT_A router bgp address-family ipv4-unicast redistribute connected enable on
nv set vrf TENANT_A router bgp address-family l2vpn-evpn enable on

# 4d - Bind the L3 VNI to the vrf. NVUE creates the VLAN 100 -> VNI 10100 mapping
# and the vlan100 SVI (no IP, in TENANT_A) by itself from these lines. Do NOT
# also add "nv set bridge domain br_default vlan 100 vni 10100" or an
# "interface vlan100" by hand - apply then fails with:
#   "VNI 10100 configured for bridge br_default already in use."
nv set vrf TENANT_A evpn enable on
nv set vrf TENANT_A evpn vlan 100
nv set vrf TENANT_A evpn vni 10100

# Review what will change, then apply
nv config diff -o commands
nv config apply -y

# Verify
nv config show -o commands | grep "^nv set router bgp"   # ASN + router-id set globally
nv show vrf TENANT_A evpn                         # L3 VNI 10100, router MAC
sudo vtysh -c "show vrf vni"                      # TENANT_A 10100 ... Up
nv show evpn vni                                  # 10100 listed as L3

-------------------------------------------------------------------------------
Step 5 - L2 VNIs and distributed anycast gateways
-------------------------------------------------------------------------------
# One block per tenant VLAN. "bridge domain ... vni" stretches the VLAN across
# the fabric. The SVI in TENANT_A with a VRR address is the anycast gateway:
# every leaf has the same gateway IP and MAC, so hosts can move between leafs
# without changing their gateway.

# WEB - VLAN 10 / VNI 10010
nv set bridge domain br_default vlan 10 vni 10010
nv set interface vlan10 type svi
nv set interface vlan10 vlan 10
nv set interface vlan10 ip vrf TENANT_A
nv set interface vlan10 ip vrr enable on
nv set interface vlan10 ip vrr address 10.20.10.254/24
nv set interface vlan10 ip vrr mac-address 44:38:39:ff:00:01

# APP - VLAN 20 / VNI 10020
nv set bridge domain br_default vlan 20 vni 10020
nv set interface vlan20 type svi
nv set interface vlan20 vlan 20
nv set interface vlan20 ip vrf TENANT_A
nv set interface vlan20 ip vrr enable on
nv set interface vlan20 ip vrr address 10.20.20.254/24
nv set interface vlan20 ip vrr mac-address 44:38:39:ff:00:02

# DB - VLAN 30 / VNI 10030
nv set bridge domain br_default vlan 30 vni 10030
nv set interface vlan30 type svi
nv set interface vlan30 vlan 30
nv set interface vlan30 ip vrf TENANT_A
nv set interface vlan30 ip vrr enable on
nv set interface vlan30 ip vrr address 10.20.30.254/24
nv set interface vlan30 ip vrr mac-address 44:38:39:ff:00:03

nv config apply -y

# Verify
nv show bridge domain br_default vlan             # 10/20/30 -> VNIs (+100 auto)
nv show evpn vni                                  # 10010/10020/10030 L2 + 10100 L3
nv show interface vlan10 ip vrr                   # 10.20.10.254/24
sudo vtysh -c "show bgp l2vpn evpn route type multicast"   # type-3 per VNI per VTEP
sudo vtysh -c "show evpn vni 10010"               # remote VTEPs (other leafs)
ip route show vrf TENANT_A                        # local 10.20.x.0/24 connected

-------------------------------------------------------------------------------
Step 6 - Endpoint access ports (test hosts)
-------------------------------------------------------------------------------
# Untagged access ports for test hosts / VMs, one per tenant VLAN. Adjust the
# swp numbers to your cabling - swp1/swp2 are the spine uplinks.
#   swp3 -> VLAN 10 (WEB)   swp4 -> VLAN 20 (APP)   swp5 -> VLAN 30 (DB)
# "bridge domain br_default access <vlan>" adds the port to the VLAN-aware
# bridge as an untagged member of that VLAN only.
nv set interface swp3 link state up
nv set interface swp3 description "TEST-HOST WEB VLAN10"
nv set interface swp3 bridge domain br_default access 10

nv set interface swp4 link state up
nv set interface swp4 description "TEST-HOST APP VLAN20"
nv set interface swp4 bridge domain br_default access 20

nv set interface swp5 link state up
nv set interface swp5 description "TEST-HOST DB VLAN30"
nv set interface swp5 bridge domain br_default access 30

# Optional - one tagged (trunk) port carrying all tenant VLANs, e.g. to a
# hypervisor or a host with VLAN sub-interfaces:
#   nv set interface swp6 link state up
#   nv set interface swp6 bridge domain br_default vlan 10,20,30
#   nv set interface swp6 bridge domain br_default untagged none

nv config apply -y

# Verify the switch side
nv show interface swp3 bridge domain br_default   # access 10
nv show bridge domain br_default vlan             # swp3/4/5 members of 10/20/30
bridge vlan show | grep -E "swp[3-5]"             # PVID / Egress Untagged

# Test PC for this leaf: PC-2 on swp4, VLAN 20, 10.20.20.12/24, gateway 10.20.20.254
# Configure the PC with the PC-2 block in samples/pc_linux_test_hosts.txt
# (Linux commands - run them on the PC, not here). Quick version, on PC-2:
#   sudo ip addr add 10.20.20.12/24 dev eth1 ; sudo ip link set eth1 up
#   sudo ip route replace 10.20.0.0/16 via 10.20.20.254 dev eth1
#
# Fabric test PCs:  PC-1 cl-lf-1 swp3 VLAN10 10.20.10.11 | PC-2 cl-lf-2 swp4 VLAN20 10.20.20.12
#                   PC-3 cl-lf-3 swp5 VLAN30 10.20.30.13 | PC-4 cl-lf-4 swp3 VLAN10 10.20.10.14

# Basic tests - run on PC-2
#   ping 10.20.20.254       # local anycast gateway
#   ping 10.20.10.11        # PC-1 on cl-lf-1, VLAN 10    -> routed over L3 VNI 10100
#   ping 10.20.30.13        # PC-3 on cl-lf-3, VLAN 30    -> routed over L3 VNI 10100

# Verify on the switch after the hosts have sent traffic
nv show bridge domain br_default mac-table        # host MACs local on swp3/4/5
sudo vtysh -c "show evpn mac vni 10010"           # local host + remote hosts via VTEPs
sudo vtysh -c "show evpn arp-cache vni 10010"     # host IP <-> MAC bindings
sudo vtysh -c "show bgp l2vpn evpn route type macip"   # type-2 for local and remote hosts
ip neigh show vrf TENANT_A                        # ARP entries in the tenant VRF
ip route show vrf TENANT_A                        # /32 host routes to remote hosts via vlan100

-------------------------------------------------------------------------------
Step 7 - Save
-------------------------------------------------------------------------------
# "apply" changes the running config; "save" makes it survive a reboot.
nv config save
nv config show -o commands                        # full config in set syntax
nv config history | head -5

-------------------------------------------------------------------------------
Notes
-------------------------------------------------------------------------------
- cl-lf-2 is a plain leaf, so it has no external WAN peering. Border leafs
  (cl-lf-5/cl-lf-6) add a numbered eBGP neighbor inside TENANT_A, e.g.
  "nv set vrf TENANT_A router bgp neighbor 192.168.100.2 remote-as 65100"
  (roles/cumulus_border_leaf/templates/nv_border_leaf.sh.j2).
- No "advertise-all-vni" or "advertise-default-gw" commands: NVUE advertises
  every local VNI once nve vxlan and the l2vpn-evpn address family are on,
  and advertise-default-gw is only for centralized-gateway designs, not the
  distributed VRR anycast gateway used here.
- See RUNBOOK.md for deeper verification and troubleshooting of each layer.
