===============================================================================
Hand-apply configuration guide - BORDER LEAF 2 (cl-bl-lf-2)
===============================================================================
Step-by-step NVUE configuration for cl-bl-lf-2, applied by hand one layer at a
time. Each step stages "nv set" commands, applies them, then verifies the
result before moving on. Steps 1-5 match the Ansible cumulus_underlay and
cumulus_overlay roles, step 6 matches the cumulus_border_leaf role.

Every line starting with "#" is a shell comment, so a whole step block can be
pasted into the switch CLI as-is.

Role in fabric : border leaf / border gateway - full L2 + L3 EVPN member of
                 the fabric (same tenant VRF / VLANs / VNIs as every leaf),
                 plus VRF-lite eBGP to both WAN/MPLS PE routers
Management IP  : 192.168.122.39
Loopback IP    : 10.0.0.16/32
VTEP IP        : 10.0.0.16
Router ASN     : 65016
Fabric MTU     : 9216 (all fabric swp links)
Uplinks        : swp1 -> cl-sp-1, swp2 -> cl-sp-2 (spine port swp6)
WAN links      : swp3 -> PE1 (AS 65101), 192.168.101.1/30 <-> 192.168.101.2
                 swp4 -> PE2 (AS 65102), 192.168.101.5/30 <-> 192.168.101.6
                 MTU 9216 (same as the fabric - PE side must match)

Tenant design (identical to every other leaf)
  VRF TENANT_A, L3 VNI 10100 (VLAN 100)
  VLAN 10 / VNI 10010  WEB  10.20.10.0/24  gw 10.20.10.254
  VLAN 20 / VNI 10020  APP  10.20.20.0/24  gw 10.20.20.254
  VLAN 30 / VNI 10030  DB   10.20.30.0/24  gw 10.20.30.254

-------------------------------------------------------------------------------
Before you start
-------------------------------------------------------------------------------
# Anything staged but not applied? (should print nothing)
nv config diff

# Throw away a half-staged change if you need to start a step again
#   nv config detach

# Leftover pre-NVUE ifupdown2 fragments break ifreload - move them out:
ls -l /etc/network/interfaces.d/
sudo mkdir -p /root/pre-nvue-backup
sudo mv /etc/network/interfaces.d/*.intf /root/pre-nvue-backup/ 2>/dev/null
ls /etc/network/interfaces.d/
ip -br link | grep -E "^vni[0-9]+"                # none expected

-------------------------------------------------------------------------------
Step 1 - Loopback and fabric uplinks
-------------------------------------------------------------------------------
nv set interface lo ip address 10.0.0.16/32

nv set interface swp1 link state up
nv set interface swp1 link mtu 9216
nv set interface swp2 link state up
nv set interface swp2 link mtu 9216

nv config apply -y

# Verify
nv show interface lo ip address           # 10.0.0.16/32
nv show interface --view=brief            # swp1/swp2 up, MTU 9216
nv show service lldp neighbor             # swp1 -> cl-sp-1, swp2 -> cl-sp-2

-------------------------------------------------------------------------------
Step 2 - Underlay BGP (eBGP unnumbered) + EVPN address family
-------------------------------------------------------------------------------
# Global BGP identity (inherited by vrf default and vrf TENANT_A).
nv set router bgp autonomous-system 65016
nv set router bgp router-id 10.0.0.16
nv set router bgp enable on

nv set vrf default router bgp peer-group UNDERLAY remote-as external
nv set vrf default router bgp peer-group UNDERLAY bfd enable on
nv set vrf default router bgp peer-group UNDERLAY address-family ipv4-unicast enable on
nv set vrf default router bgp peer-group UNDERLAY address-family l2vpn-evpn enable on

nv set vrf default router bgp neighbor swp1 type unnumbered
nv set vrf default router bgp neighbor swp1 peer-group UNDERLAY
nv set vrf default router bgp neighbor swp2 type unnumbered
nv set vrf default router bgp neighbor swp2 peer-group UNDERLAY

nv set vrf default router bgp address-family ipv4-unicast network 10.0.0.16/32
nv set vrf default router bgp address-family ipv4-unicast multipaths ebgp 2
nv set vrf default router bgp address-family l2vpn-evpn enable on

nv set vrf default router bgp enable on

nv config apply -y

# Verify
nv show vrf default router bgp neighbor           # swp1, swp2 established
sudo vtysh -c "show bgp summary"
sudo vtysh -c "show bgp l2vpn evpn summary"
ping -c3 -I lo 10.0.0.1                           # spine loopback reachable

-------------------------------------------------------------------------------
Step 3 - VXLAN tunnel endpoint (VTEP)
-------------------------------------------------------------------------------
nv set nve vxlan enable on
nv set nve vxlan source address 10.0.0.16

nv config apply -y

# Verify
nv show nve vxlan                                 # enabled, source 10.0.0.16

-------------------------------------------------------------------------------
Step 4 - Tenant VRF and L3 VNI (symmetric IRB)
-------------------------------------------------------------------------------
# Same ASN/router-id lines as step 2, repeated so this step works on its own.
nv set router bgp autonomous-system 65016
nv set router bgp router-id 10.0.0.16
nv set router bgp enable on

# Remove any hand-made L3 VNI mapping (ignore messages if none exists).
nv unset bridge domain br_default vlan 100
nv unset interface vlan100

# BGP instance inside the tenant vrf. "redistribute connected" turns the
# tenant subnets into EVPN type-5 routes.
nv set vrf TENANT_A router bgp enable on
nv set vrf TENANT_A router bgp address-family ipv4-unicast enable on
nv set vrf TENANT_A router bgp address-family ipv4-unicast redistribute connected enable on
nv set vrf TENANT_A router bgp address-family l2vpn-evpn enable on

# 4c-2 - ECMP inside the vrf. The WAN default route arrives as type-5 from
# both border leafs (and on a border leaf from both PEs), each from a
# different ASN - the AS paths never match, so BGP needs aspath-ignore to
# install both.
nv set vrf TENANT_A router bgp path-selection multipath aspath-ignore on
nv set vrf TENANT_A router bgp address-family ipv4-unicast multipaths ebgp 2

# Bind the L3 VNI. NVUE creates VLAN 100 -> VNI 10100 and the vlan100 SVI itself;
# do NOT add them by hand.
nv set vrf TENANT_A evpn enable on
nv set vrf TENANT_A evpn vlan 100
nv set vrf TENANT_A evpn vni 10100

nv config diff -o commands
nv config apply -y

# Verify
nv show vrf TENANT_A evpn                         # L3 VNI 10100, router MAC
sudo vtysh -c "show vrf vni"                      # TENANT_A 10100 ... Up
nv show evpn vni                                  # 10100 listed as L3

-------------------------------------------------------------------------------
Step 5 - L2 VNIs and distributed anycast gateways (L2 extension)
-------------------------------------------------------------------------------
# Same VLANs, VNIs, gateway IPs and VRR MACs as every other leaf, so the
# border leaf is a full member of each stretched L2 segment and an anycast
# gateway for each subnet.

# WEB - VLAN 10 / VNI 10010
nv set bridge domain br_default vlan 10 vni 10010
nv set interface vlan10 type svi
nv set interface vlan10 vlan 10
nv set interface vlan10 ip vrf TENANT_A
nv set interface vlan10 ip vrr enable on
nv set interface vlan10 ip vrr address 10.20.10.254/24
nv set interface vlan10 ip vrr mac-address 44:38:39:ff:00:01

# APP - VLAN 20 / VNI 10020
nv set bridge domain br_default vlan 20 vni 10020
nv set interface vlan20 type svi
nv set interface vlan20 vlan 20
nv set interface vlan20 ip vrf TENANT_A
nv set interface vlan20 ip vrr enable on
nv set interface vlan20 ip vrr address 10.20.20.254/24
nv set interface vlan20 ip vrr mac-address 44:38:39:ff:00:01

# DB - VLAN 30 / VNI 10030
nv set bridge domain br_default vlan 30 vni 10030
nv set interface vlan30 type svi
nv set interface vlan30 vlan 30
nv set interface vlan30 ip vrf TENANT_A
nv set interface vlan30 ip vrr enable on
nv set interface vlan30 ip vrr address 10.20.30.254/24
nv set interface vlan30 ip vrr mac-address 44:38:39:ff:00:01

nv config apply -y

# Verify
nv show bridge domain br_default vlan             # 10/20/30 -> VNIs
nv show evpn vni                                  # 10010/10020/10030 L2 + 10100 L3
nv show interface vlan10 ip vrr                   # 10.20.10.254/24
sudo vtysh -c "show bgp l2vpn evpn route type multicast"   # type-3 from all leafs
sudo vtysh -c "show evpn vni 10010"               # remote VTEPs
ip route show vrf TENANT_A

-------------------------------------------------------------------------------
Step 6 - Border gateway: VRF-lite eBGP to PE1 and PE2 (L3 extension to WAN)
-------------------------------------------------------------------------------
# swp3 (PE1) and swp4 (PE2) are routed ports in TENANT_A with numbered /30s.
# The PEs are outside the unnumbered underlay, so these are numbered eBGP
# sessions inside the tenant vrf. MTU 9216 (jumbo, same as the fabric) for the
# multi-site Cumulus <-> Arista path - the PE interfaces must match.
#
# Policy in one line: accept ONLY the default route from the PEs, advertise
# ONLY the tenant summary 10.20.0.0/16 to them, and load-share (ECMP) both
# ways.

# 6a - Tenant summary. Built from the connected tenant /24s (the vlan10/20/30
# SVIs from step 5), so it is always present on a border leaf. Deliberately
# NOT summary-only: that would suppress the /24s for EVPN too - WAN_OUT
# below keeps the /24s away from the PEs instead.
nv set vrf TENANT_A router bgp address-family ipv4-unicast aggregate-route 10.20.0.0/16

# 6b - Prefix-lists and route-maps
nv set router policy prefix-list DEFAULT_ROUTE rule 10 match 0.0.0.0/0
nv set router policy prefix-list DEFAULT_ROUTE rule 10 action permit
nv set router policy prefix-list TENANT_SUMMARY rule 10 match 10.20.0.0/16
nv set router policy prefix-list TENANT_SUMMARY rule 10 action permit

# To the PEs: the summary only. Rule 20 denies everything else (the /24s,
# /32 host routes, the WAN /30s, and the default route learned from the
# other PE - so the fabric never becomes a transit path between PE1 and PE2).
nv set router policy route-map WAN_OUT rule 10 match ip-prefix-list TENANT_SUMMARY
nv set router policy route-map WAN_OUT rule 10 action permit
nv set router policy route-map WAN_OUT rule 20 action deny

# From the PEs: the default route only.
nv set router policy route-map WAN_IN rule 10 match ip-prefix-list DEFAULT_ROUTE
nv set router policy route-map WAN_IN rule 10 action permit
nv set router policy route-map WAN_IN rule 20 action deny

# Only if you applied the earlier version of this guide (per-/24 policy):
#   nv unset router policy prefix-list TENANT_SUBNETS

# 6c - PE-facing links and eBGP sessions
# PE1 - swp3
nv set interface swp3 description "cl-bl-lf-2 -> PE1 (WAN/MPLS edge)"
nv set interface swp3 link state up
nv set interface swp3 link mtu 9216
nv set interface swp3 ip address 192.168.101.1/30
nv set interface swp3 ip vrf TENANT_A

nv set vrf TENANT_A router bgp neighbor 192.168.101.2 type numbered
nv set vrf TENANT_A router bgp neighbor 192.168.101.2 remote-as 65101
nv set vrf TENANT_A router bgp neighbor 192.168.101.2 description PE1
nv set vrf TENANT_A router bgp neighbor 192.168.101.2 bfd enable on
nv set vrf TENANT_A router bgp neighbor 192.168.101.2 address-family ipv4-unicast enable on
nv set vrf TENANT_A router bgp neighbor 192.168.101.2 address-family ipv4-unicast policy inbound route-map WAN_IN
nv set vrf TENANT_A router bgp neighbor 192.168.101.2 address-family ipv4-unicast policy outbound route-map WAN_OUT

# PE2 - swp4
nv set interface swp4 description "cl-bl-lf-2 -> PE2 (WAN/MPLS edge)"
nv set interface swp4 link state up
nv set interface swp4 link mtu 9216
nv set interface swp4 ip address 192.168.101.5/30
nv set interface swp4 ip vrf TENANT_A

nv set vrf TENANT_A router bgp neighbor 192.168.101.6 type numbered
nv set vrf TENANT_A router bgp neighbor 192.168.101.6 remote-as 65102
nv set vrf TENANT_A router bgp neighbor 192.168.101.6 description PE2
nv set vrf TENANT_A router bgp neighbor 192.168.101.6 bfd enable on
nv set vrf TENANT_A router bgp neighbor 192.168.101.6 address-family ipv4-unicast enable on
nv set vrf TENANT_A router bgp neighbor 192.168.101.6 address-family ipv4-unicast policy inbound route-map WAN_IN
nv set vrf TENANT_A router bgp neighbor 192.168.101.6 address-family ipv4-unicast policy outbound route-map WAN_OUT

# 6d - Re-advertise the default route into EVPN as type-5 (next-hop = this
# VTEP), so every other leaf gets two ECMP exits - one per border leaf.
# ECMP across PE1 + PE2 on this box comes from the vrf multipath lines in
# step 4c-2.
nv set vrf TENANT_A router bgp address-family ipv4-unicast route-export to-evpn enable on

nv config diff -o commands
nv config apply -y

# Verify - sessions
nv show interface swp3                            # up, 192.168.101.1/30, vrf TENANT_A
nv show interface swp4                            # up, 192.168.101.5/30, vrf TENANT_A
sudo ip vrf exec TENANT_A ping -c3 192.168.101.2         # PE1
sudo ip vrf exec TENANT_A ping -c3 192.168.101.6         # PE2
nv show vrf TENANT_A router bgp neighbor          # 192.168.101.2 and .6 established
sudo vtysh -c "show bfd vrf TENANT_A peers brief"

# Verify - policy
sudo vtysh -c "show bgp vrf TENANT_A ipv4 unicast neighbors 192.168.101.2 routes"              # 0.0.0.0/0 only
sudo vtysh -c "show bgp vrf TENANT_A ipv4 unicast neighbors 192.168.101.2 advertised-routes"   # 10.20.0.0/16 only
sudo vtysh -c "show bgp vrf TENANT_A ipv4 unicast neighbors 192.168.101.6 advertised-routes"   # 10.20.0.0/16 only
sudo vtysh -c "show bgp vrf TENANT_A ipv4 unicast 10.20.0.0/16"   # aggregated by 65016, local

# Verify - ECMP
sudo vtysh -c "show bgp vrf TENANT_A ipv4 unicast 0.0.0.0/0"   # 2 paths, both "multipath" (PE1 + PE2)
ip route show vrf TENANT_A default                # 2 nexthops: via 192.168.101.2 dev swp3, via 192.168.101.6 dev swp4
sudo vtysh -c "show bgp l2vpn evpn route type prefix" | grep -B1 -A3 "0.0.0.0"   # exported, RD 10.0.0.16:x

# Verify - on a normal leaf (cl-lf-1)
#   ip route show vrf TENANT_A default            # 2 nexthops: via 10.0.0.15 and 10.0.0.16 (vlan100 onlink)

nv config save
nv config show -o commands
nv config history | head -5

-------------------------------------------------------------------------------
Notes
-------------------------------------------------------------------------------
- Unlike cl-lf-1..4 there are no endpoint access ports in this sample: the
  border leaf's outside-facing role is the WAN links in step 6. Add access
  ports as in step 6 of cl-lf-1 if you want test hosts here too.
- Dual border leafs: cl-bl-lf-1 runs the same step 6 with its own /30s
  (192.168.100.0/30 to PE1, 192.168.100.4/30 to PE2). Each border leaf exports the
  default route as type-5 with its own VTEP as next-hop, so cl-lf-1..4 get
  two ECMP paths and lose nothing if one border leaf, PE or link fails. If a
  border leaf loses both PEs it still has the other border leaf's default
  via EVPN (longer AS path, used only as a backup).
- ECMP towards the fabric is on the PE side. Each PE hears 10.20.0.0/16 from
  AS 65015 and AS 65016 - different AS paths - so it needs multipath-relax
  as well as maximum-paths. It must also send the default route. Cisco IOS
  example for PE1 (PE2: AS 65102, neighbors 192.168.100.5 / 192.168.101.5):

    router bgp 65101
     bgp bestpath as-path multipath-relax
     address-family ipv4 vrf TENANT_A
      neighbor 192.168.100.1 remote-as 65015
      neighbor 192.168.100.1 activate
      neighbor 192.168.100.1 default-originate
      neighbor 192.168.100.1 fall-over bfd
      neighbor 192.168.101.1 remote-as 65016
      neighbor 192.168.101.1 activate
      neighbor 192.168.101.1 default-originate
      neighbor 192.168.101.1 fall-over bfd
      maximum-paths 2

  plus "mtu 9216" and "bfd interval 300 min_rx 300 multiplier 3" on both
  PE-facing interfaces, and the VRF itself (rd / route-target) for the MPLS backbone.
  Check with "show ip bgp vpnv4 vrf TENANT_A 10.20.0.0" - two paths, multipath.
- The spines peer with this box on swp6 (type unnumbered, peer-group
  UNDERLAY) - see the cl-sp-1/cl-sp-2 samples.
