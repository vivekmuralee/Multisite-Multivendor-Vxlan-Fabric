===============================================================================
Hand-apply configuration guide - NTP, DNS and banners (all Cumulus switches)
===============================================================================
Same commands on every switch (cl-sp-1/2, cl-lf-1..4, cl-bl-lf-1/2) except the
MOTD's second and third lines. NTP and DNS run on the Kubernetes cluster
(kubernetes/README.md, --tags netsvc) and are reached through the management
VRF (eth0, vrf mgmt):

  DNS  192.168.122.64  CoreDNS, authoritative for lab.internal and
                       122.168.192.in-addr.arpa, recursive for everything else
  NTP  192.168.122.65  chrony, synced to time.cloudflare.com / pool.ntp.org

Verified on Cumulus Linux 5.4.0. Every line starting with "#" is a shell
comment, so each block can be pasted as-is (as user cumulus). The same
commands are generated by roles/cumulus_underlay (nv_underlay.sh.j2).

-------------------------------------------------------------------------------
Before you start
-------------------------------------------------------------------------------
# Anything already staged but not applied? MUST print nothing - otherwise
# "nv config apply" below applies that half-finished work too.
nv config diff

# What NTP servers are configured now? (some switches had 8.8.8.8, which is
# Google DNS, not an NTP server)
nv config show -o commands | grep "service ntp"

-------------------------------------------------------------------------------
Step 1 - NTP
-------------------------------------------------------------------------------
# Remove each server the command above listed, e.g.:
nv unset service ntp mgmt server 8.8.8.8

# iburst: send a burst of 4 queries at start, so the first sync takes seconds,
# not minutes.
nv set service ntp mgmt server 192.168.122.65 iburst on

-------------------------------------------------------------------------------
Step 2 - DNS
-------------------------------------------------------------------------------
# Writes "nameserver 192.168.122.64 # vrf mgmt" to /etc/resolv.conf.
# NVUE 5.4 has no search-domain setting, so use full names:
#   ping -I mgmt cl-lf-2.lab.internal     (not: ping cl-lf-2)
nv set service dns mgmt server 192.168.122.64

-------------------------------------------------------------------------------
Step 3 - Banners
-------------------------------------------------------------------------------
# pre-login: shown before the password prompt (/etc/issue.net, sshd "Banner").
nv set system message pre-login "Authorized access only. Activity on this device is monitored and logged."

# post-login (/etc/motd). "nv set" rejects a value containing newlines, so the
# multi-line MOTD is staged with "nv config patch", which takes the same change
# as YAML (the format "nv config diff" prints). Edit lines 2-3 per switch:
cat > /tmp/nv_motd.yaml <<'MOTD'
- set:
    system:
      message:
        post-login: |
          ================================================================================
            cl-lf-1  |  Leaf  |  Multisite VXLAN EVPN fabric (lab)
            Mgmt: 192.168.122.34 (vrf mgmt)  |  ASN 65011  |  VTEP 10.0.0.11
          --------------------------------------------------------------------------------
            Config is applied by hand with NVUE (cumulus/samples/): stage with nv set,
            review with "nv config diff", then "nv config apply".
          ================================================================================
MOTD
nv config patch /tmp/nv_motd.yaml
rm -f /tmp/nv_motd.yaml

# Per-switch values for lines 2-3 (spines have no VTEP):
#   cl-sp-1     Spine        Mgmt 192.168.122.32  ASN 65001
#   cl-sp-2     Spine        Mgmt 192.168.122.33  ASN 65002
#   cl-lf-1     Leaf         Mgmt 192.168.122.34  ASN 65011  VTEP 10.0.0.11
#   cl-lf-2     Leaf         Mgmt 192.168.122.35  ASN 65012  VTEP 10.0.0.12
#   cl-lf-3     Leaf         Mgmt 192.168.122.36  ASN 65013  VTEP 10.0.0.13
#   cl-lf-4     Leaf         Mgmt 192.168.122.37  ASN 65014  VTEP 10.0.0.14
#   cl-bl-lf-1  Border leaf  Mgmt 192.168.122.38  ASN 65015  VTEP 10.0.0.15
#   cl-bl-lf-2  Border leaf  Mgmt 192.168.122.39  ASN 65016  VTEP 10.0.0.16

-------------------------------------------------------------------------------
Apply
-------------------------------------------------------------------------------
# Should list only the NTP, DNS and message changes above:
nv config diff
nv config apply -y

-------------------------------------------------------------------------------
Verify (ntpd restarts on apply; give it 1-2 min to select the server)
-------------------------------------------------------------------------------
sudo ip vrf exec mgmt ntpq -pn
#   *192.168.122.65  162.159.200.1  4 u ...     "*" = selected source
#   ".STEP." in the refid column right after apply is normal; wait a minute.
#   (timedatectl says "NTP service: inactive" - it only tracks systemd-timesyncd,
#    not ntp@mgmt, so ignore it.)

cat /etc/resolv.conf
#   nameserver 192.168.122.64 # vrf mgmt
sudo ip vrf exec mgmt dig +short arista-lf-1.lab.internal
#   192.168.122.28
sudo ip vrf exec mgmt dig +short -x 192.168.122.24
#   arista-sp-1.lab.internal.

cat /etc/motd /etc/issue.net
# Log out and back in to see both banners.

-------------------------------------------------------------------------------
Rollback
-------------------------------------------------------------------------------
nv unset service ntp mgmt server 192.168.122.65
nv unset service dns mgmt server 192.168.122.64
nv unset system message
# re-add the previous servers if you want them, then:
nv config apply -y
